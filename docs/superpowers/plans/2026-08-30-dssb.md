# DSSB 与沙盒内具名程序互调 Implementation Plan

> **For agentic workers:** Use the subagent-driven-development skill to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不引入宿主 PATH、跨 sandbox RPC 或嵌套 flake/git 的前提下，为 ocsb 增加严格校验的具名程序 API，并交付官方 `@deepseek-ai/dsh@0.1.1-rc.2` 的可复现 Nix 包、DSSB 模块、持久化 wrapper、flake outputs、回归测试、文档与 CI/Cachix 构建路径。

**Architecture:** 通用层在 `modules/programs.nix` 定义 `programs.<command>.package/binPath`，`lib/mkSandbox.nix` 把批量 `packages` 与逐项校验后的具名程序合成为唯一 `/usr/bin`，并按 `<app.binPath 所在目录>:/usr/bin:<可写 profiles>` 设置三个 backend 共用的 PATH。DSSB 保持为根仓库直接跟踪的 `dssb/` 子目录：固定 npm lock/hash 的 DSH derivation 由 `module.nix` 注入现有 `mkSandbox`，外层 `wrapper.nix` 只负责持久化、参数边界和调用者 cwd；本地测试始终替换为 fake DSH，官方 payload 仅由独立 CI job 构建并推送 Cachix。

**Tech Stack:** Nix flakes、Nix module system、Nixpkgs `buildNpmPackage`/`prefetch-npm-deps`、Node.js 22、npm lockfile v3、Bash、bubblewrap、可选 Podman/Docker、GitHub Actions、Cachix。

**Spec:** `docs/superpowers/specs/2026-08-30-dssb-design.md`

**Global Constraints:**
- 官方上游固定为 `https://github.com/deepseek-ai/deepseek-harness`；只打包 npm 已发布的 `@deepseek-ai/dsh@0.1.1-rc.2`，CLI 入口为 `lib/bin.js`。
- Node 约束必须保持 `^22.19.0 || >=24.0.0`；DSH tarball integrity 必须保持 `sha512-UP1UIh6q3Gme/yXRn/QL2P8IsVlv8Shpg22TRJIZPsCRWLm4CBiA1MUvXmJAfsOEETBMLAl+xWPtFw6ICsN3wg==`。
- `dssb/` 是根仓库普通目录；不得创建嵌套 `.git`、`.gitmodules`、独立 `flake.nix`/`flake.lock` 或虚构 subtree remote；设计要求的 `package-lock.json` 是唯一子项目依赖锁。
- `nixModules.dssb` 是 ocsb 配置模块，不是 NixOS 系统模块；根 flake 必须公开 `packages.<system>.dsh` 与 `packages.<system>.dssb`。
- `programs.<command>.package` 的类型为 `lib.types.package`；`programs.<command>.binPath` 的类型为非空、非绝对、无 `..` 路径段的 `lib.types.str`；`programs` 的类型为上述 submodule 的 `lib.types.attrsOf`。
- `dssb.package` 的类型为 `lib.types.package`，默认 `pkgs.callPackage ./package.nix { }`；`dssb.extraPrograms` 与通用 `programs` 使用完全相同的 attrset/submodule 结构和校验规则。
- 具名 command 只允许 shell-safe 名称，禁止 `/`、空白、前导 `-` 和任意 `..`；target 必须同时是普通文件（`-f`）和 executable（`-x`），缺失、目录、不可执行目标以及与批量 `packages` 的命令冲突必须 fail closed。
- 沙盒 PATH 固定为 `<app.binPath 所在目录>:/usr/bin:/home/sandbox/.nix-profile/bin:/nix/var/nix/profiles/default/bin`；无 app package 时从 `/usr/bin` 开始。不得导入 host PATH。
- `app.daemon` 只保证先 spawn 再启动前台程序，不承诺 readiness；依赖服务的前台程序必须自行轮询可观察健康状态。
- DSSB 默认 `network.enable = true`；systemd-nspawn 必须继续明确拒绝 filtered network，不能静默降级。默认 `packages.dssb` 不把沙盒 loopback/端口转发到宿主；宿主浏览器访问只能由下游显式 `network.enable = lib.mkForce null;` 选择 host network，并承认这是放宽隔离。
- `@deepseek-ai/dsh@0.1.1-rc.2` 只承诺随 npm 包提供的 `web` 与 `headless` profiles；不得宣称该版本含其他未发布 bundle。`dssb web --no-open` 是 web profile 的进程调用，不是默认宿主可访问 Web UI 承诺；不得新增自动端口、跨实例 socket 或 runtime 网络 flag。允许通过 profile/plugin 机制创建自定义组合，模块必须通过 `programs.pnpm` 声明式提供根 nixpkgs 的 `pkgs.pnpm`（当前版本线 11.15）供 `dsh plugin` 调用。由于 `bin/pnpm -> ../libexec/...` 是相对链接，pnpm 不属于批量 `packages`；它以具名绝对 store target 暴露为 `/usr/bin/pnpm`，不同的 `dssb.extraPrograms.pnpm` 定义会 module leaf conflict 并 fail closed。
- `dssb/package.nix` 不得通过 package-level `npmFlags` 全局禁用 lifecycle scripts，也不得覆盖 `configurePhase` 或手写 `npm ci`/`npm rebuild`。根锁定 Nixpkgs 的 `npmConfigHook` 内部先执行 `npm ci --ignore-scripts`，随后自动且仅一次执行 `npm rebuild "${npmRebuildFlags[@]}" "${npmFlags[@]}"`；默认 flags 不含全局 `--ignore-scripts`，因此 dependency lifecycle 已由 hook 执行。`postConfigure` 只运行无需 API key 的 `node-pty` PTY native smoke 并产出固定 marker `DSSB_NODE_PTY_NATIVE_OK`。
- wrapper 不得使用 `eval` 处理 DSH argv，不得自动捕获 secret-like 环境变量；`DEEPSEEK_API_KEY` 只能由用户显式 `--env DEEPSEEK_API_KEY` 转发或写入 mode 0600 的 `$DSH_HOME/.credentials.yaml`。
- 本地不得构建官方 DSH payload；本地只生成/校验 lock 与 npm cache hash、执行 `nix flake check --no-build`、构建 ocsb/fake fixtures 并运行回归测试。官方 `dsh`/`dssb` 构建属于 CI/Cachix。
- 所有父会话终端命令从 PowerShell 发起；组合 shell 语法必须封装在 `wsl -d nixos -- bash -lc 'cd /mnt/c/Users/hugefiver/source/ocsb && ...'` 中。
- Commit Guard 使新增文件在实现结束前可能保持 untracked；本地 flake evaluation/build 必须使用 `path:$PWD` installable（测试内部使用 `builtins.getFlake "path:$REPO_ROOT"`），不得用 `git add` 让 Nix 看见新文件。CI checkout 中的已跟踪 revision 仍使用普通 `.#...` installable。
- Commit Guard：本计划不含 commit、push、tag 或其他 Git 写步骤；实现阶段也不得在没有新的明确授权时执行 Git 写命令。

**Scenario matrix:**

| Kind | Scenario | Observable result |
|---|---|---|
| Happy | 主程序从非 `bin/` 的 `app.binPath` 调用具名 `peer` | argv、stdin、stdout、stderr 保真，peer 的退出码 23 成为前台退出码 |
| Happy | daemon 调用 `peer`，前台程序自行轮询 marker | daemon marker 先出现；没有新增 readiness 承诺 |
| Happy | `peer` 调用 app package 同目录的 `main-helper` | 输出 `APP_HELPER_OK`，证明 PATH 使用 `app.binPath` 所在目录 |
| Happy | peer package 还包含未声明的第二个 executable | 第二个 executable 不在 PATH，证明单条 program 不泄漏整包 binaries |
| Edge | command 含空白、`/`、前导 `-` 或 `..`；`binPath` 为空、绝对或含 `..` segment | eval 失败且消息含 `programs`/`binPath` |
| Edge | target 缺失 | build 失败并输出 `target does not exist` 与具体 command/target |
| Edge | target 是 mode 0755 目录 | build 失败并输出 `target is not a regular file`，不能因目录具有 executable bit 而通过 |
| Edge | target 是普通文件但无 executable bit | build 失败并输出 `target is not executable` |
| Edge | 同一 Nix attrset 重复声明 command | Nix attrset evaluation 失败，不产生后写覆盖 |
| Edge | `packages` 已暴露同名 command | build 失败；不得静默覆盖 |
| Regression | writable profile 中存在同名 `peer` | `/usr/bin/peer` 获胜，输出仍来自声明式 peer |
| Regression | Podman/nspawn launcher | 仍从公共 `/usr/bin` bind 与 PATH 生成 plan；systemd-nspawn filtered 边界不变 |

- [ ] **Step 3: 实现 `modules/programs.nix` 并导入根 module**

  `modules/programs.nix` 使用下列确定的类型和校验，不放宽字符集：

  ```nix
  { lib, ... }:
  let
    validCommand = command:
      builtins.match "^[A-Za-z0-9][A-Za-z0-9._+-]*$" command != null
      && !(lib.hasInfix ".." command);

    validBinPath = path:
      path != ""
      && !(lib.hasPrefix "/" path)
      && !(builtins.elem ".." (lib.splitString "/" path));

    programType = lib.types.submodule ({ ... }: {
      options = {
        package = lib.mkOption {
          type = lib.types.package;
          description = "Package containing the single named sandbox command.";
        };
        binPath = lib.mkOption {
          type = lib.types.addCheck lib.types.str validBinPath;
          example = "libexec/tool";
          description = "Non-empty package-relative executable path without '..' segments.";
        };
      };
    });
  in
  {
    options.programs = lib.mkOption {
      type = lib.types.attrsOf programType;
      default = { };
      apply = value:
        assert lib.assertMsg
          (lib.all validCommand (builtins.attrNames value))
          "programs command names must match ^[A-Za-z0-9][A-Za-z0-9._+-]*$ and cannot contain '..'";
        value;
      description = "Named programs exposed one command at a time inside the sandbox.";
    };
  }
  ```

  在 `modules/default.nix` 中紧跟 `./packages.nix` 添加 `./programs.nix`。不要更改 `packages` 的批量暴露兼容语义。

- [ ] **Step 4: 在 `lib/mkSandbox.nix` 构造 fail-closed command directory**

  把当前单一 `sandboxBin` 拆成以下确定的 let bindings；错误文本供测试精确匹配：

  ```nix
  packageBin = pkgs.symlinkJoin {
    name = "${cfg.app.name}-package-bin";
    paths = [ pkgs.bashInteractive ] ++ cfg.packages;
  };

  namedProgramsBin = pkgs.runCommand "${cfg.app.name}-named-programs-bin" { } ''
    mkdir -p "$out/bin"
    ${lib.concatMapStringsSep "\n" (command:
      let
        program = cfg.programs.${command};
        target = "${program.package}/${program.binPath}";
      in
      ''
        if [[ ! -e ${lib.escapeShellArg target} ]]; then
          echo ${lib.escapeShellArg "ocsb: programs.${command} target does not exist: ${target}"} >&2
          exit 1
        fi
        if [[ ! -f ${lib.escapeShellArg target} ]]; then
          echo ${lib.escapeShellArg "ocsb: programs.${command} target is not a regular file: ${target}"} >&2
          exit 1
        fi
        if [[ ! -x ${lib.escapeShellArg target} ]]; then
          echo ${lib.escapeShellArg "ocsb: programs.${command} target is not executable: ${target}"} >&2
          exit 1
        fi
        if [[ -e ${lib.escapeShellArg "${packageBin}/bin/${command}"} ||
              -L ${lib.escapeShellArg "${packageBin}/bin/${command}"} ]]; then
          echo ${lib.escapeShellArg "ocsb: programs.${command} conflicts with packages command '${command}'"} >&2
          exit 1
        fi
        ln -s ${lib.escapeShellArg target} "$out/bin/${command}"
      '') (builtins.attrNames cfg.programs)}
  '';

  sandboxBin = pkgs.symlinkJoin {
    name = "${cfg.app.name}-sandbox-bin";
    paths = [ packageBin namedProgramsBin ];
  };
  ```

  `closureInfoDrv.rootPaths` 明确包含 `packageBin`、`namedProgramsBin` 和 `sandboxBin`；即使 symlink reference scanning 已可传递 closure，也保留三个 root 以使安全边界可审计。不要为每个 program 创建独立 sandbox mount，也不要把其包目录加入 PATH。

- [ ] **Step 5: 按 `app.binPath` 所在目录修正 PATH**

  用 `builtins.dirOf` 计算目录，保留 app 优先级并把 `/usr/bin` 放在 writable profiles 前：

  ```nix
  appBinDir =
    if cfg.app.package != null
    then "${cfg.app.package}/${builtins.dirOf cfg.app.binPath}"
    else null;

  nixProfilePath = "/home/sandbox/.nix-profile/bin:/nix/var/nix/profiles/default/bin";

    lib.optional (appBinDir != null) appBinDir
  ```
